Fabric app build guide

Rayfin football match centre

From empty workspace to a live replay of Barcelona 5-0 Real Madrid streaming through Eventstream, Eventhouse and a Rayfin app with predictions. Budget about two hours the first time; most of it is waiting for Fabric items to provision.

0What you are building

replay_match.py ──▶ Eventstream (custom endpoint) │ ▼ Eventhouse: raw_events ──update policy──▶ match_events │ KQL functions: Scoreline, XgRace, Momentum, ShotMap, PassNetwork, PlayerStats, KeyMoments │ DirectQuery semantic model (M parameter Match_Id) │ Rayfin app (React) ◀── DAX via host bridge / connector / Power BI REST │ Rayfin data service: Prediction, ScoutingNote, WatchedMatch

Prerequisites

  • A Fabric workspace on a capacity (F2 trial is enough) where you are Admin or Member.
  • Tenant setting Fabric Apps enabled by a Fabric admin (Admin portal → Tenant settings → search "Fabric App"). Without this rayfin up fails at item creation.
  • Node.js 20 or later and npm on your machine. Check with node -v.
  • Python 3.10 or later for the replay producer.
  • The repo rayfin-football unpacked locally. All paths below are relative to its root.
  • Optional: Power BI Desktop, which makes the semantic model step faster than the web editor.

1Workspace and naming

5 minutes

  1. Create or pick a workspace. Suggested name: Football Match Centre. Keep everything in one workspace; the Rayfin connector and the semantic model both resolve items by workspace id.
  2. Note the workspace id from the URL: app.fabric.microsoft.com/groups/<workspace-id>/.... You will paste it in steps 5 and 6.
  3. Decide item names now so the rest of the guide reads literally:
    • Eventhouse Football_EH, KQL database Football_DB
    • Eventstream ES_MatchEvents
    • Semantic model Football_Model
    • Fabric App rayfin-football (comes from rayfin/rayfin.yml)

2Eventhouse and KQL schema

10 minutes

  1. In the workspace, New item → Eventhouse, name Football_EH. It creates a KQL database of the same name; rename it to Football_DB or keep the default and adjust names later.
  2. Open the KQL database and copy the Query URI from the database details pane (looks like https://xxxx.z1.kusto.fabric.microsoft.com). Also note the database id (the GUID in the URL).
  3. Open a KQL queryset on the database. Paste the whole of fabric/eventhouse/DatabaseSchema.kql, put the cursor anywhere inside the .execute database script block and press Run. The queryset runs only the block under the cursor, so the file is written as one command that runs everything in order. The result grid shows one row per command; every row should read Completed.
  4. The script uses .create-merge and .create-or-alter, so it is safe to re-run. If an earlier attempt left a half-built match_events table, run .drop table match_events ifexists first.
Check
.show functions lists Parse_Match_Events, Scoreline, XgRace, Momentum, ShotMap, PassNetwork, PlayerStats, KeyMoments.
.show table match_events policy update shows IsEnabled: true with source raw_events.
.show table raw_events ingestion json mappings shows raw_events_mapping.
Why two tables
Eventstream lands the full JSON object in raw_events.content. The update policy flattens it into typed columns in match_events on ingestion, so every query runs against real types with no tostring() noise. This is the same pattern the Helsinki transport template uses.

3Eventstream

10 minutes

  1. New item → Eventstream, name ES_MatchEvents. Open it in edit mode.
  2. Add source → Custom endpoint. Name it MatchEvents_Source. Leave defaults.
  3. Add destination → Eventhouse:
    • Data ingestion mode: Direct ingestion. The other mode infers a fixed schema from the stream and flags a schema mismatch on the nested content object.
    • Workspace: yours. Eventhouse: Football_EH. KQL database: Football_DB
    • Click Save. Table and mapping are set in the Eventhouse afterwards (step 6 below).
  4. Publish the Eventstream. Wait until the status reads Active (one to three minutes).
  5. Select the custom endpoint source → Keys tab → copy Connection string-primary key. It already contains EntityPath=…, which is the event hub name; nothing else is needed.
  6. Send 20 sample events so the next step has data to preview (setup in step 4): python ingest/replay_match.py --events ingest/data/events_69299.json --no-wait --limit 20
  7. On the Eventhouse destination tile click Configure. In the Get data wizard: Existing table → raw_events, format JSON, Advanced → Use existing mapping → raw_events_mapping. Finish.
  8. Cut the ingestion batching window from the default five minutes to ten seconds, otherwise the app lags minutes behind the replay: .alter table raw_events policy ingestionbatching '{"MaximumBatchingTimeSpan":"00:00:10","MaximumNumberOfItems":500,"MaximumRawDataSizeMB":100}'
  9. A new data connection only picks up events sent after it was created, so send the 20 test events again now. After about 30 seconds check raw_events | count and match_events | count; both should be 20. Then clear the test rows: .clear table raw_events data and .clear table match_events data.
Check
The Eventstream canvas shows source → stream → Eventhouse destination with no warning icons. The destination tile shows raw_events.
Alternative
fabric/eventstream/eventstream.json is the same definition with placeholders, ready for the Fabric REST API or Fabric CLI if you prefer to script it. The Helsinki template's fabric/deploy/03_eventstream.py shows the exact API call.

4Replay the match

15 minutes including the first full replay

  1. Install the producer dependency once: 
    cd rayfin-football
python3 -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r ingest/requirements.txt
  2. Dry run to see the envelope shape; nothing is sent: 
    python ingest/replay_match.py --events ingest/data/events_69299.json --dry-run --limit 20
    You should see one JSON object per line with match_id, minute, type, team, x, y, and for shots xg and is_goal.
  3. Set the connection string from step 3 and backfill the whole match quickly so you have data to build the model against: 
    export EVENTSTREAM_CONNECTION_STRING="Endpoint=sb://...;SharedAccessKeyName=...;SharedAccessKey=...;EntityPath=..."
python ingest/replay_match.py --events ingest/data/events_69299.json --no-wait
    Expect # done: 1565 events within about 30 seconds. The replay streams 1,565 curated events: passes, shots, dribbles, duels, cards, subs. Ball receipts, carries and pressures are filtered out; add --all-types if you want all 3,975.
  4. Wait about a minute for ingestion, then verify in the KQL queryset: 
    Scoreline(69299)
Expected result
teamgoalsshotsxgpassespass_pct
Barcelona5112.7772388.1
Real Madrid060.1337173.9
Then run XgRace(69299), Momentum(69299), ShotMap(69299), PassNetwork(69299), PlayerStats(69299), KeyMoments(69299). Each should return rows. Momentum is the one with window logic; if it errors on prev(), replace the window line with a self-join on minute between minute - windowMinutes + 1 and minute.
Replay speeds
--speed 10 replays 90 minutes in about 9 minutes (stage demo). --speed 50 in under 2. --start-minute 45 jumps to the second half. To reset between demos run .clear table raw_events data and .clear table match_events data in KQL.

5Semantic model (DirectQuery)

25 minutes

The app speaks DAX, not KQL, because the three browser transports (Fabric host bridge, Rayfin connector, Power BI REST) all target a semantic model. The model is seven thin DirectQuery tables, one per KQL function, driven by a single parameter.

  1. Open Power BI Desktop → Get data → Azure Data Explorer (Kusto). Cluster: the Query URI from step 2. Database: Football_DB. Pick DirectQuery. Connect with your Fabric account, then cancel the navigator so no table is loaded yet.
  2. Open Transform data (Power Query). Manage parameters → New parameter: name Match_Id, type Decimal Number, current value 69299, required.
  3. Create a blank query named Scoreline with this M (Advanced Editor), replacing the cluster URL and database GUID: 
    let
    Source = AzureDataExplorer.Contents(
        "https://xxxx.z1.kusto.fabric.microsoft.com",
        "00000000-0000-0000-0000-000000000000",
        "Scoreline(" & Number.ToText(Match_Id) & ")",
        [MaxRows=null, MaxSize=null, NoTruncate=null, AdditionalSetStatements=null])
in
    Source
  4. Duplicate the query six times, renaming each and changing only the KQL call:
    Query nameKQL
    XgRace"XgRace(" & Number.ToText(Match_Id) & ")"
    Momentum"Momentum(" & Number.ToText(Match_Id) & ", 5)"
    ShotMap"ShotMap(" & Number.ToText(Match_Id) & ")"
    PassNetwork"union (PassNetwork(" & Number.ToText(Match_Id) & ", 'Barcelona') | extend team='Barcelona'), (PassNetwork(" & Number.ToText(Match_Id) & ", 'Real Madrid') | extend team='Real Madrid')"
    PlayerStats"PlayerStats(" & Number.ToText(Match_Id) & ")"
    KeyMoments"KeyMoments(" & Number.ToText(Match_Id) & ", 50)"
    Close and apply. Confirm every table shows storage mode DirectQuery in Model view (hover the table header). An Import table here silently freezes the app.
  5. Model view: no relationships are needed. Set minute, x, y and all numeric columns to Don't summarize so DAX SELECTCOLUMNS returns raw rows.
  6. Publish to the workspace as Football_Model. In the service, open the model settings → Data source credentials and sign in with OAuth2 if prompted.
  7. Note the semantic model id from its URL (/datasets/<id>). You need it twice in step 6.
Check
In the service, open the model → Explore (or DAX query view in Desktop) and run: 
DEFINE MPARAMETER 'Match_Id' = 69299
EVALUATE 'Scoreline'
Two rows, matching the table in step 4. If MPARAMETER errors, the parameter was not bound to DirectQuery; recreate it with "required" ticked.
Web-only route
No Desktop? In the KQL database choose Power BI semantic model from the ribbon, add the seven functions as tables, then edit each table's M in the web modelling editor to add the parameter. It works but the parameter UI is clumsier.

6Rayfin app: local run

20 minutes

  1. Install and sign in: 
    cd rayfin-football
npm install
npx rayfin login            # opens a browser; use the account that owns the workspace
  2. Provision the app in your workspace once. Without --workspace-id the CLI deploys to "My Workspace". Preview first with --dry-run, then run it for real: 
    npx rayfin up --workspace-id <workspace-id> --exclude-services staticHosting --dry-run
npx rayfin up --workspace-id <workspace-id> --exclude-services staticHosting
    The first deploy writes the app's Fabric properties to rayfin/.env, which later runs read. If a later npm run dev creates a second app in My Workspace, add --workspace-id to the dev script in package.json.
  3. Create the app environment file: 
    cp .env.example .env.local.overrides
    Fill in:
    • VITE_PBI_DATASET_ID - the semantic model id from step 5. Required on all transports.
    • VITE_PBI_CLIENT_ID and VITE_PBI_TENANT_ID - only for running the app standalone in a browser tab (the Power BI REST fallback). Inside the Fabric portal the host bridge is used and these are not needed. To create the app registration: Entra ID → App registrations → New, single-page application, redirect URI http://localhost:5173, API permissions → Power BI Service → delegated Dataset.Read.All.
  4. Optional server-side transport: in rayfin/rayfin.yml replace the two zero GUIDs under connectors.matchModel.config with the workspace id and the semantic model id. Leave it if you only run embedded in the portal.
  5. Provision auth and data, then start Vite: 
    npm run dev
    This runs rayfin up --exclude-services staticHosting first, which creates the Fabric App item, provisions the SQL database from the three entities in rayfin/data/, publishes the GraphQL API, and writes .env.local with the five VITE_RAYFIN_* and VITE_FABRIC_* values. Then Vite serves on http://localhost:5173.
  6. Open the app, click Sign in with Fabric. The header shows the Clásico at 0-0 with "waiting for events" until the first query returns, then flips to LIVE with the 5-0 from the backfill.
Check
Submit a prediction (it will say locked if the match already has events; clear the KQL tables first or temporarily set live to false in App.tsx). Then in the Fabric portal open the app's SQL database and query SELECT * FROM Prediction. Your row is there with user_id set to your Entra object id.
Entities
Prediction: everyone reads, only the owner writes (claims.sub.eq(item.user_id)). ScoutingNote: owner-only on every operation. WatchedMatch: any signed-in user reads and writes, for the demo. Edit a decorator and run npx rayfin up again; schema changes propagate to the database and the typed client.

7Deploy to Fabric

10 minutes

  1. Build and deploy everything including static hosting: 
    npx rayfin up
    The CLI runs npm run build:fabric, uploads dist/, and prints the app URL inside the Fabric portal.
  2. Open the Fabric App item in the workspace. It loads the built app with Fabric SSO; no second sign-in, since the host bridge runs DAX as the portal user.
  3. If you use the standalone URL as well, add it as an SPA redirect URI on the Entra app registration from step 6, and append it to allowedRedirectUris in rayfin/rayfin.yml, then rayfin up again.
Check
The LIVE indicator is green and the key moments list shows Jeffrén 90+' at the top. Open the app on a phone: the stat grid collapses to two columns and the shot map stays within the screen.

8Run the demo

10 minutes on stage

  1. Before the session: clear both KQL tables, open the Fabric App, confirm 0-0 and the prediction form is open.
  2. Ask the room for a score. Submit two or three predictions from different accounts if you have them.
  3. Start the replay at 10x in a visible terminal: 
    python ingest/replay_match.py --events ingest/data/events_69299.json --speed 10
  4. Minute 9 (about 55 seconds in): Xavi scores. Header flips, xG race separates, first goal dot on the shot map.
  5. Minute 17: Pedro. Switch to the KQL queryset and run PlayerStats(69299) | top 5 by progressive_passes to show Messi and Xavi driving play.
  6. Half time comes fast; the producer skips the break. Point out the momentum chart going one-sided.
  7. Minutes 54 and 57: Villa twice. Then show the predictions list; nobody picked 5-0.
  8. Optional closers: an Activator rule on match_events | where is_goal posting to Teams; a Data Agent over Football_Model asked "who had the most progressive passes in the second half".

9Troubleshooting

SymptomCause and fix
raw_events fills, match_events emptyUpdate policy not attached or function errors. Run Parse_Match_Events() | take 5 directly; fix the column that fails, then re-run the .alter table ... policy update command.
Eventstream shows data, KQL shows nothingMapping name mismatch. Either set raw_events_mapping on the destination or drop the mapping and let Eventstream map by name.
App shows "waiting for events" foreverModel table is Import, not DirectQuery, or VITE_PBI_DATASET_ID is wrong. Verify with the DAX check in step 5.
"Sign in to Power BI" banner in the portalHost bridge not available in this portal build; the app fell back to REST. Fill in client and tenant ids, or use the Rayfin connector in rayfin.yml.
ConnectorFunction invocation is not enabledThe fabric-semanticmodel connector is still gated per workspace. Remove the connector block; the gateway picks the next transport automatically.
rayfin up fails creating the Fabric App itemTenant setting Fabric Apps is off, or your role in the workspace is Viewer or Contributor.
Prediction create returns 403The user_id you send does not match the JWT sub. The hook reads it from client.auth.getSession().user.id; make sure the session is live.
Momentum() errorsSee step 4. The function uses prev() with an offset; some engine versions want the self-join form.
Producer: ServiceBusError or 401Connection string copied without EntityPath, or the Eventstream is not yet Active. Re-copy the key after publish.
